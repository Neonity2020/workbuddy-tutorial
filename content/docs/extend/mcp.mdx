MCP（Model Context Protocol）是一个开放协议，用统一的方式把外部工具和数据源接给 AI。连接器是别人做好的集成，MCP 是你可以自己搭的那层。

## 什么时候该自己接

- 要访问**内部系统**：自建 API、内网数据库、公司知识库。
- 要用**现成开源服务**：Playwright、GitHub、本地文件系统等社区 MCP。
- 连接器市场里**没有**你需要的那个系统。

## 配置

配置文件在用户目录下的 `~/.workbuddy/mcp.json`（注意不是 `.mcp.json`）。如果文件已存在，**合并**新的条目，不要覆盖已有服务。

```json
{
  "mcpServers": {
    "my-server": {
      "command": "npx",
      "args": ["-y", "@some/mcp-server@latest"],
      "env": {
        "API_KEY": "your-key"
      }
    }
  }
}
```

远程服务用 URL 形式：

```json
{
  "mcpServers": {
    "remote": {
      "type": "http",
      "url": "https://example.com/mcp",
      "headers": {
        "Authorization": "Bearer your-token"
      }
    }
  }
}
```

<Callout type="warn" title="字段别猜">
`command` / `args` / `env` / `url` / `headers` 这些字段的写法，以服务提供方文档为准。自己发明字段通常不会报错，只会静默不生效，很难排查。
</Callout>

## 生效

改完配置**不会自动生效**。到连接器管理页右上角的「自定义连接器」入口，找到新加的服务并点击**信任**，才会加载。

<Callout type="tip">
这是有意设计的：MCP 服务能执行任意本地命令，必须由你显式确认一次。
</Callout>

## 在任务里的表现

会话需要 MCP 服务时，对话流会给出连接进度：

- 显示「正在连接 MCP 服务」及已连接数/总数，连接成功实时更新。
- 可展开查看明细，按**已连接**与**未连接**分组列出服务名。
- 全部完成后显示「所有 MCP 服务已就绪」，这段进度随即从对话流消失，不留历史记录。

如果某个 MCP 提供交互界面，WorkBuddy 可以在对话或右侧产物区直接渲染该界面，你在里面选选项、填内容、提交操作即可继续任务。打不开时先检查服务是否已连接，再重新发起任务。

## 管控

**设置 → 安全中心 → 工具管控 → MCP 页**：

- 按 MCP 服务整体启停。
- 支持逐工具控制的服务可展开单独配置。
- 「自定义 MCP」总开关关闭后，所有自己添加的 MCP 都不可调用。

配置保存在本地，对当前客户端内所有 Agent 生效，改完即时生效。

## 排查清单

| 现象 | 先查什么 |
| --- | --- |
| 服务没加载 | 是否点了「信任」；JSON 是否合法 |
| 启动就失败 | `command` 在本机是否存在；`npx` 能否联网拉包 |
| 连上但工具调不动 | 工具管控里是否被禁用；凭证是否过期 |
| 偶发超时 | 远程服务网络；是否被安全中心的网络规则拦了 |

调试期可以先把「AI 安全防护」关掉，用确定性规则排查，找到问题再开回来。

## 安全边界

MCP 服务拥有你给它的能力，可能是读文件、跑命令、访问网络。所以：

- 只从可信来源安装。
- 密钥写在 `env` 里，别提交进 Git。
- 不需要时在工具管控里关掉，而不是留着不管。
- 第三方 MCP 的返回内容也可能包含诱导指令，必要时开启「工具内容注入防护」。
