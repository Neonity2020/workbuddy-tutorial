技能解决「会不会」，连接器解决「够不着」。连接器（Connector）是一层预先做好的授权通道：接上之后，WorkBuddy 能在你授权范围内读写第三方系统。

## 什么时候需要

任务里出现这些句子时，通常就在等一个连接器：

- 「把结果同步到腾讯文档」
- 「查一下 TAPD 上这个需求的进展」
- 「把这份周报发到企业微信的群里」
- 「从我的邮箱里找出上周的合同附件」

## 怎么接

<Steps>
  <Step title="进入连接器页">
    侧边栏 **专家·技能·连接器 → 连接器** 页签。
  </Step>
  <Step title="找到目标服务">
    按分类或搜索定位。已经绑定的会显示为已连接，可随时查看详情或断开。
  </Step>
  <Step title="授权">
    点击连接，按引导完成 OAuth 或 Token 授权。授权范围以该服务的说明为准。
  </Step>
  <Step title="在任务中使用">
    直接说需求即可。任务真正需要时，WorkBuddy 也会主动弹出连接引导卡片，点连接后**自动继续**当前任务。
  </Step>
</Steps>

<Callout type="tip" title="不用提前全部接上">
连接引导只在任务实际用到某个服务时出现，不会一开始就列出所有依赖。按需接，接得少，授权面就小。
</Callout>

## 三个常见问题

### 认证过期

表现为原本能用的服务突然报授权失败。重新连接一次即可，不需要新建任务。如果是上游认证失效，优先在连接器管理里重新授权，而不是反复重试同一操作。

### 只读还是可写

不同连接器的能力边界不同。有的只读（查数据、拉记录），有的可写（建文档、发消息、改状态）。**写操作要格外小心**：发出去的消息、改掉的状态很难撤回。

建议在涉及批量写、群发、状态流转的任务里，先加一句约束：

```text
批量操作前先把将要修改的对象列成清单，等我确认后再执行。
```

### 权限范围

连接器用的是**你本人的授权**。这意味着：

- 你能看到的东西，它才看得到；
- 你能改的东西，它才改得动；
- 授权在第三方系统里可以随时撤销，撤销后连接器立即失效。

## MCP 与连接器的关系

连接器是「开箱即用」的集成，MCP 是「自己搭」的协议层。前者省事，后者灵活。需要接内部系统、自建服务时看 [MCP 集成](/docs/extend/mcp)。

## 和资料库的分工

容易混的一对：

| | 连接器 | 资料库 |
| --- | --- | --- |
| 数据在哪 | 第三方系统里 | WorkBuddy 自己的空间里 |
| 主要动作 | 读写外部系统 | 沉淀、检索、复用 |
| 典型用法 | 同步周报到腾讯文档 | 把历史周报存起来，下次直接检索 |

经常一起用：连接器把外部内容拉进来，资料库把它存住。
