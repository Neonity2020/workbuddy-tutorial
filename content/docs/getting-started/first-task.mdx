这个练习刻意选了一个小但真实的场景：**把一份杂乱的销售流水整理成带图表的汇总报告**。做完你会理解 WorkBuddy 的工作方式，而不只是「它会聊天」。

## 准备材料

新建一个空文件夹，比如 `~/Documents/wb-demo`，放一个 `sales.csv` 进去。没有数据就随便写几行：

```csv
日期,城市,产品,数量,单价
2026-08-01,北京,A款,12,199
2026-08-02,上海,B款,8,299
2026-08-03,广州,A款,20,199
2026-08-04,深圳,C款,5,499
2026-08-05,北京,B款,15,299
```

<Callout type="tip" title="为什么要单独建文件夹">
WorkBuddy 的默认权限以工作空间为边界。把待处理文件放进独立目录，它读写时不会被反复拦下来问确认，你也不用担心它碰到别的文件。
</Callout>

## 第一步：新建任务并选工作空间

在首页输入框左下角点击**选择工作空间**，选到 `wb-demo`。选择完成后，本次任务的读写范围就锁定了。

## 第二步：把需求写清楚

在输入框里粘贴这段话：

```text
读取 sales.csv，按城市汇总销售数量和金额，金额 = 数量 × 单价。
生成一份 Word 报告 report.docx，包含：
1. 一段 100 字以内的整体结论
2. 一张城市销售额对比表格
3. 一张城市销售额柱状图
数字保留两位小数，货币用人民币符号。
```

<Callout type="note" title="这段话为什么有效">
它同时给齐了四件事：**数据源**（sales.csv）、**计算口径**（金额怎么算）、**输出格式**（Word）、**验收标准**（三块内容、两位小数）。缺任何一项，WorkBuddy 都要自己猜，猜错就得返工。
</Callout>

## 第三步：看它干活

发送后，对话区会实时展示执行过程：读文件、算数据、写文档、画图表，每一步都有阶段说明和可展开的中间结果。右侧结果区会同步出现产物卡片。

整个过程你不用盯着，可以去做别的事。任务完成后会有提示。

## 第四步：验收与迭代

打开 `report.docx`，发现柱状图颜色太花？不用重新描述需求，直接在对话框里补一句：

```text
柱状图改成统一的蓝色系，标题改成「各城市销售额对比」。
```

WorkBuddy 会基于当前上下文修改，而不是从头再来。这就是"对话式推进"的价值——**改一处，不用重述全部**。

如果某一版改坏了，可以把对话**回退**到这条消息之前，产物会一起回到那个版本。

## 第五步：并行的第二个任务

保持当前任务不动，回到首页新建一个任务，试试：

```text
把 sales.csv 转成 Excel，按城市拆成多个 sheet，每个 sheet 加一行合计。
```

两个任务互不干扰，左侧任务列表里可以来回切换。

## 你已经用到的能力

| 能力 | 在哪里体现 |
| --- | --- |
| 多步骤规划 | 读数据 → 汇总 → 写文档 → 插图，自动串起来 |
| 本地文件读写 | 直接读 `sales.csv`，直接写 `report.docx` |
| 结果交付 | 右侧结果区提供预览与下载 |
| 上下文延续 | 追加一句话就能改指定部分 |
| 版本回退 | 改坏了能退回上一版 |
