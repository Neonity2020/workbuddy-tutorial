## 让输出更稳的四句

```text
先不要执行，列出你需要我确认的信息，最多 5 条。
```

```text
把任务拆成步骤，先给我看计划，确认后再执行。
```

```text
完成后自查：数据是否一致、格式是否符合要求、有没有遗漏的结构项。有问题先修再交付。
```

```text
如果某项要求无法满足，直接说明原因，不要用替代方案蒙混。
```

最后一句很重要。模型天然倾向于"交付点什么"，宁可编一个也不说做不到。明确给它"说做不到"的许可。

## 控制风格

| 想要 | 写法 |
| --- | --- |
| 简洁 | 「每段不超过 3 行，删掉所有过渡句和总结句」 |
| 正式 | 「书面语，不用第一人称，不用口语词，不用感叹号」 |
| 去 AI 味 | 「避免排比、避免『不仅…更是…』、少用形容词，多用具体数字和事实」 |
| 有观点 | 「每个判断给出理由，允许下明确结论，不要模棱两可」 |
| 模仿某人 | 上传两篇样本，「沿用这个作者的句式和节奏」 |

## 控制结构

```text
按这个骨架输出，不要增删章节：
1. 一句话结论
2. 三个支撑事实（每个带数字）
3. 一个反方视角
4. 建议（不超过三条，每条有动作主体和时间）
```

骨架给得越具体，返工越少。反过来，如果你也不确定结构，就先让它出三个不同结构的提纲让你挑。

## 分步走，别一次到位

复杂任务分三轮，比一次说清更省时间：

<Steps>
  <Step title="第一轮：对焦">
    「我要做 X，先给我三个不同的思路，各一句话。」
  </Step>
  <Step title="第二轮：定方案">
    「选第 2 个，展开成详细提纲。」
  </Step>
  <Step title="第三轮：填充">
    「按这个提纲写，风格参考我上传的样本。」
  </Step>
</Steps>

每一轮你都只花十几秒确认，但避免了在错误方向上跑十分钟。

## 约束的写法

模糊约束 = 没有约束。对比：

| 模糊 | 明确 |
| --- | --- |
| 「简短一点」 | 「全文不超过 800 字」 |
| 「专业一点」 | 「使用行业术语，首次出现时给英文原文」 |
| 「数据准确」 | 「每个数字标注来源文件名和行号」 |
| 「排版好看」 | 「一级标题 18pt 加粗，段间距 6pt」 |
| 「多给几个方案」 | 「给三个方案，分别是成本优先、速度优先、质量优先」 |

## 让它引用而不是编造

```text
只使用我提供的材料回答。材料里没有的信息，明确写「材料未提及」，不要补充常识或推测。
每条结论后面标注它来自哪个文件的哪一段。
```

这一条能把幻觉率压到很低。代价是有些问题它会答"不知道"——但你需要的是准确，不是流畅。

## 反面清单

<Callout type="warn" title="这几种说法几乎一定返工">
- **「你懂的」**：它不懂，它只有你的字面意思。
- **「随便」「都行」**：它会选最省步骤的那个。
- **「参考一下网上」**：没说范围，可能给你三年前的数据。
- **「做得高级一点」**：形容词没有可执行含义。
- **一次列 12 条要求**：容易漏掉中间几条，尤其是一句话里塞了多个并列。
</Callout>

## 一个可复用的开头

不知道怎么写时，用这个模板起手，再按需增删：

```text
【目标】我要 [产出物]，用于 [场景/读者]。
【输入】材料在 [文件/目录]，关键信息是 [要点]。
【输出】格式 [Word/Excel/PPT/网页]，结构 [章节列表]，篇幅 [字数/页数]。
【约束】[口径/风格/必须包含/必须避免]。
【验收】完成后请自查 [检查项]，并说明你的处理方式。
```
