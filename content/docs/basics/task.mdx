WorkBuddy 的核心是理解自然语言，所以「怎么说话」直接决定产出质量。好消息是它不需要你学语法，坏消息是**含糊的需求它也会认真执行**——然后给你一个认真但错误的结果。

## 它需要知道四件事

<Steps>
  <Step title="目标">
    要生成什么、要处理什么。是「一份周报」还是「整理目录里的图片」。
  </Step>
  <Step title="输入">
    用哪份数据、参考哪个文档。有文件就点名文件。
  </Step>
  <Step title="输出格式">
    Word、Excel、PPT、网页还是纯文本。格式不同，执行路径完全不同。
  </Step>
  <Step title="约束">
    风格、字数、计算口径、截止时间、必须包含的章节。
  </Step>
</Steps>

## 一句话 vs 一个任务

| 说法 | 结果 |
| --- | --- |
| 「帮我做个销售分析」 | 它会自己造口径，你不一定认 |
| 「按城市汇总 sales.csv 的销售额，金额=数量×单价，生成一页 PPT，含一个柱状图和三条结论」 | 基本一次到位 |

差别不在长度，在**可验证性**。第二句话你能一眼判断对错，第一句不能。

## 提示词模板

新建任务页按场景（日常办公、代码开发、设计创意）提供了一组模板。鼠标悬停在模板上，输入框里会显示灰色预览文案——**预览不会进入草稿，也不会计入发送内容**，确认合适再点击才真正填入。

常用模板如下，可以直接抄：

<Tabs items={['文档', '数据分析', 'PPT', '调研']}>
  <Tab value="文档">
    ```text
    根据 [输入文件]，生成一份 [文档类型]，主题是 [主题]。
    结构：摘要 / 背景 / 分析 / 结论 / 建议。
    语气：正式，面向 [读者]。
    字数：[范围]。输出为 Word。
    ```
  </Tab>
  <Tab value="数据分析">
    ```text
    读取 [文件]，按 [维度] 分组，计算 [指标]。
    处理规则：[空值/异常值怎么处理]。
    输出：一张汇总表 + 一张趋势图，Excel 格式。
    ```
  </Tab>
  <Tab value="PPT">
    ```text
    基于 [材料] 做一份 [页数] 页的 PPT，面向 [听众]。
    结构：[章节列表]。
    每页不超过 3 个要点，图表优先于文字。
    ```
  </Tab>
  <Tab value="调研">
    ```text
    调研 [主题]，聚焦 [时间范围/地区]。
    需要：市场规模的量级、主要玩家、三条关键趋势。
    每个结论标注来源。输出 Markdown 报告。
    ```
  </Tab>
</Tabs>

## 上下文比修辞重要

同一个需求，多给一份参考文档，效果可能翻倍：

<Cards>
  <Card title="引用上下文" href="/docs/basics/conversation">
    用 `@` 引用文件、文档、规则，让 WorkBuddy 直接读原始材料。
  </Card>
  <Card title="粘贴截图" href="/docs/basics/conversation">
    `Ctrl/Cmd + V` 直接贴图，比文字描述界面问题快得多。
  </Card>
  <Card title="上传文件" href="/docs/basics/conversation">
    拖拽到输入框即可。支持 PDF、Office、图片、压缩包和常见代码文件。
  </Card>
  <Card title="补充说明" href="/docs/advanced/prompt">
    目标、范围、约束、预期输出，写清楚一条少返工一轮。
  </Card>
</Cards>

## 语音输入

输入框有语音按钮，说出来的话实时转成文字填进输入框。适合需求长、懒得打字的时候——比如一边翻资料一边口述一份报告结构。

## 让它先问你

不确定需求该怎么拆时，加一句：

```text
先不要开始执行，列出你需要我确认的信息，最多 5 条。
```

WorkBuddy 会停下来提问，而不是猜。这一步花 30 秒，常常省掉两轮返工。

## 三个反模式

<Callout type="warn" title="「你看着办」">
它真的会看着办，选择标准是「最省步骤」而不是「最合你意」。
</Callout>

<Callout type="warn" title="一次塞十个需求">
多目标混在一条消息里，容易漏。拆成几条按顺序发，或者明确说「按 1-5 顺序逐项完成」。
</Callout>

<Callout type="warn" title="把关键信息放在最后一句">
长需求里，结论性的约束（「必须用 A 方案」「不要改原文件」）要放在开头或单独强调，埋在末尾容易被忽略。
</Callout>
