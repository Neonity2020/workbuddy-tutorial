文档是 WorkBuddy 最成熟的产线。它不强在"会写"，强在**它真的会排版**——生成的是 `.docx` 文件，不是一段 Markdown 让你自己贴。

## 一个能用的完整指令

```text
读取 meeting-notes.md 和 q3-data.xlsx，生成 Q3 经营分析报告 report-q3.docx。

结构：
1. 执行摘要（200 字以内，三条结论）
2. 关键指标（表格：营收、毛利率、同比、环比）
3. 分区域分析（每个区域一段，含一句判断）
4. 问题与风险（不超过四条）
5. 下季度建议（三条，可执行）

要求：正式书面语，不用第一人称，数据保留两位小数，表格加表头底色。
```

<Callout type="tip" title="结构直接写出来">
不要只说「按标准格式」。把你心里的目录写出来，它照着搭骨架，你只需要改内容。这一步能省掉最多轮返工。
</Callout>

## 让它更像"你写的"

最有效的办法不是描述风格，而是**给它一个样本**：

```text
参考 style-sample.docx 的写作风格和排版（标题层级、字号、行距、页眉页脚），
按同样风格写这次的内容。
```

风格样本 + 内容素材，比十句形容词管用。

## 排版细节怎么提

| 你要的效果 | 怎么说 |
| --- | --- |
| 标题层级 | 「一级标题用黑体三号，二级用黑体小四」 |
| 页眉页脚 | 「页眉放报告名，页脚放页码，奇偶页不同」 |
| 表格 | 「表格三线表，表头灰底，数字右对齐」 |
| 图表 | 「图表居中，图注在图下方，编号连续」 |
| 分页 | 「每章另起一页」 |

## 长文档的稳妥打法

一次生成 50 页，容易前后不一致。分两步：

<Steps>
  <Step title="先定骨架">
    「先只输出目录和每节要点，不要展开，等我确认。」
  </Step>
  <Step title="确认后逐节展开">
    「按确认的目录写第 1、2 章。」再「继续第 3 章，保持同样风格。」
  </Step>
  <Step title="最后统一收口">
    「全文通读一遍，统一术语（统一用『客户』不用『用户』），检查编号和交叉引用。」
  </Step>
</Steps>

## 常见返工及对策

<Callout type="warn" title="「太像 AI 写的」">
加约束：「避免排比句和『不仅仅是…更是…』句式，每段不超过 4 行，少用形容词，多给具体数字」。
</Callout>

<Callout type="warn" title="数据对不上">
把计算口径写进指令：「营收=订单金额合计，不含运费」。让它把计算过程写进附录，便于核对。
</Callout>

<Callout type="warn" title="格式在别人电脑上错位">
交付前用目标版本（WPS / Office 2016 / 365）分别打开一次。字体缺失是最常见原因，把正文改成宋体/黑体这类通用字体最稳。
</Callout>

## 和文档技能的关系

如果客户端装了文档类技能，WorkBuddy 会走技能内的专业排版流水线（封面、版式、目录自动化），效果比通用生成更稳定。写重要文档时值得先确认技能已启用。

## 一次完整交付的检查项

- [ ] 目录页码和正文对得上
- [ ] 表格数字与源数据抽查一致
- [ ] 图表编号连续、图注完整
- [ ] 页眉页脚没有串页
- [ ] 没有残留的占位文字（"XX"、"待补充"）
- [ ] 文件名和版本号符合团队规范
