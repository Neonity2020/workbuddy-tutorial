数据分析是最能体现"人机分工"的场景：你负责定口径和判断，它负责清洗、计算、出图、写结论。

## 第一步：先看数据，别急着分析

```text
读取 sales.csv，先不要分析，只告诉我：
1. 有多少行多少列，各列类型
2. 每列的空值数、重复值数、取值范围
3. 你发现的三处数据质量问题
```

这一步能省掉后面所有返工。真实的销售表里总有：日期格式不统一、金额带货币符号、城市名有空格、负数代表退货但没标注。

## 第二步：定口径

指令里必须显式写清算法，不要让它猜：

```text
计算规则：
- 销售额 = 数量 × 单价，退款行（数量为负）计入销售额，但单独统计退款率
- 时间维度按自然月，以订单日期为准
- 剔除测试订单（客户名包含"测试"）
输出：按月份和城市两个维度的汇总表
```

<Callout type="warn" title="口径不清是最大的坑">
"总销售额"这三个字至少有四种算法：含不含退款、含不含税、按下单日还是发货日、含不含运费。你不写，它选一个看起来合理的，然后你在汇报现场被问住。
</Callout>

## 第三步：分析 + 出图

```text
基于清洗后的数据：
1. 计算月度销售额趋势、环比增速
2. 找出销售额下滑最严重的三个城市，给出可能原因假设
3. 生成 Excel：原始清洗表、月度汇总、城市排名三个 sheet
4. 附一张趋势折线图和一张城市对比条形图
5. 图表配色统一用蓝色系，标题写明数据范围和时间
```

## 让它自我校验

这是最值得加的一句：

```text
计算完成后，用另一种方法独立验证总额，如果两种方法结果不一致，说明差异原因。
```

它会把汇总表的合计和原始表的 `sum` 对一遍。数字对不对，是分析报告唯一的底线。

## 输出什么格式

| 需求 | 格式 |
| --- | --- |
| 继续加工、给别人填数 | Excel，多 sheet，保留公式 |
| 汇报、给管理层看 | PPT + 一页结论 |
| 归档、留痕 | CSV + 一份说明计算口径的 Markdown |
| 要交互筛选 | 网页看板（可发布成链接） |

## 一份好的分析长什么样

不是图表越多越好。稳定的结构是：

1. **结论**（一句话，带数字）
2. **支撑**（2–3 个关键指标的变化）
3. **原因**（可验证的假设，不是"因为市场竞争激烈"这种废话）
4. **建议**（能落地，有责任人和时间）

可以让它按这个结构写：

```text
结论部分不超过 100 字，只讲一个最重要的发现；
原因部分每条都要能对应到数据里的具体现象；
建议部分不要出现"加强""提升""优化"这类没有动作的词。
```

## 常见坑

<Callout type="warn" title="图表骗人">
纵轴不从 0 开始、双轴图、用面积表示长度——这些都会放大或缩小视觉差异。要求「所有柱状图纵轴从 0 开始」。
</Callout>

<Callout type="warn" title="相关性当因果">
「两个指标同涨」不等于「A 导致 B」。让它区分「相关」和「因果」，因果结论必须给机制解释。
</Callout>

<Callout type="warn" title="样本太小">
分组后每组只剩三五条数据时，任何结论都不可靠。要求它输出每组样本量，低于阈值直接标注「样本不足」。
</Callout>
